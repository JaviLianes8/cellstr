Ranked by user impact. Every item is additive: the 0.1.0 functions keep their names,
positional parameters and return types. New behaviour arrives through new functions and
keyword-only parameters. The package has not been published yet, so the default width of
emoji sequences moves from "sum of code points" to "one glyph", which is what modern
terminals draw.

1. **Width tables from the real Unicode data.** The 0.1.0 table is a hand-vendored
   Unicode 15.1 extract. Replace it with tables generated by a committed script from a
   committed UCD 18.0.0 snapshot (EastAsianWidth.txt, DerivedGeneralCategory.txt,
   emoji-data.txt, GraphemeBreakProperty.txt, DerivedCoreProperties.txt), following
   Markus Kuhn's wcwidth rules: Mn, Me and Cf are zero (except SOFT HYPHEN), Hangul
   medial vowels and final consonants are zero, W and F are two. A test regenerates the
   tables and compares them byte for byte.
2. **Grapheme-aware width.** Measure extended grapheme clusters (UAX #29) instead of code
   points: a ZWJ family emoji, a skin tone sequence, a regional indicator flag and a
   keycap are each one wide glyph. VS16 turns a text-default emoji wide, VS15 makes an
   emoji narrow. The full GraphemeBreakTest.txt runs in the suite. New public
   `iter_graphemes()` and `grapheme_width()`.
3. **Grapheme-safe slicing.** `cell_slice` never splits a cluster: an accent stays on its
   letter, a flag is never halved, a wide glyph that straddles an edge is dropped whole.
4. **Ambiguous-width policy.** East Asian Ambiguous characters (Greek, Cyrillic, box
   drawing, circled digits) are one cell in Western locales and two in CJK terminals.
   Every function takes `ambiguous=1` or `ambiguous=2`.
5. **Tab handling.** Opt-in `tabsize=` advances to the next tab stop while measuring,
   and slicing or padding turns tabs into the spaces they cover so the result keeps its
   layout. New `expand_tabs()` that is ANSI and width aware.
6. **Truncation that fits real layouts.** `truncate(..., position="end" | "start" |
   "middle")` for paths and identifiers, `fit()` to truncate and pad to an exact width in
   one call, and `truncate_detailed()` returning a frozen `Truncation` result.
7. **Typed cell iteration.** `iter_cells()` yields frozen `Cell` records (text, width,
   column, escape flag) so callers can build their own layouts without re-measuring.
8. **ANSI coverage.** Keep ignoring SGR and OSC 8 hyperlinks when measuring and keep them
   when slicing; add DCS, SOS, PM and APC strings, charset designations and 8-bit CSI.
9. **Command line tool.** `cellstr measure`, `cellstr truncate N`, `cellstr pad N`,
   `cellstr fit N` and `cellstr slice START STOP` over stdin lines, with `--ambiguous`
   and `--tabsize`, runnable examples in `--help`, errors on stderr with exit status 1.
10. **Docs.** Full docstrings, a GUIDE that explains the width rules, where terminals
    disagree (with concrete examples) and how to pick a policy.
11. **Proof.** Contract test over the whole promise with UCD-derived vectors, a
    cross-check of every code point against the `wcwidth` package (test-only oracle) with
    the differences documented, seeded fuzzing of slicing and truncation, and an
    end-to-end test that builds the wheel, installs it into a throwaway venv and drives
    the installed `cellstr` script.
