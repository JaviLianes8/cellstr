# cellstr

[![Lianes8 Certified](https://lianes8studio.com/certified/lianes8-certified-badge.svg)](https://lianes8studio.com/certified)

Display-width aware `len`, slicing, padding and truncation for terminal text: East Asian
wide characters, emoji sequences, combining marks, zero-width characters and ANSI escape
sequences, measured the way a terminal draws them. Typed, zero dependencies, Unicode 18.0.0.

## Install

```
pip install cellstr
```

## Usage

`len`, slicing and `str.ljust` count code points, so they misalign any text that carries
colour codes, CJK characters, emoji or accents. `cellstr` counts display cells.

```python
from cellstr import cell_len, cell_slice, fit, ljust, truncate

warn = "\x1b[31mWARN\x1b[0m"  # red "WARN"
cell_len(warn)  # -> 4
cell_len("你好")  # -> 4
cell_len("👨‍👩‍👧")  # -> 2
cell_len("🇯🇵")  # -> 2
cell_len("é")  # -> 1

cell_slice(warn, 0, 2)  # -> "\x1b[31mWA\x1b[0m"
cell_slice("a你b", 0, 2)  # -> "a"
cell_slice("x👨‍👩‍👧y", 0, 2)  # -> "x"

ljust("你", 4)  # -> "你  "
truncate("hello world", 8)  # -> "hello..."
truncate("/usr/local/lib/python", 12, position="middle")  # -> "/usr/...thon"
fit("张伟张伟", 5, suffix="")  # -> "张伟 "
```

What it gets right:

- **Grapheme clusters.** A ZWJ family, a skin tone sequence, a flag, a keycap or a letter
  with accents is one unit: measured once and never split by slicing or truncation.
- **Escape sequences.** SGR colours, OSC 8 hyperlinks, cursor movement and the other
  ECMA-48 families, in their 7-bit form (starting with ESC), count as nothing and are kept
  in place, so styled text stays styled. An escape still ends the grapheme cluster before
  it, so the text that `strip_ansi` returns can measure differently (see the GUIDE).
  Cutting or padding never turns a stray ESC and the text after it into a new sequence. The 8-bit C1 introducers such as U+009B are
  zero-width controls, and what follows them counts as text.
- **Ambiguous width.** Greek, Cyrillic, box drawing and circled digits are one cell in
  Western terminals and two in CJK ones. Pass `ambiguous=2` to any function that measures
  (all of them except `strip_ansi` and `iter_graphemes`).
- **Tabs.** Pass `tabsize=8` to measure tab stops; slicing and padding turn tabs into the
  spaces they cover. `expand_tabs()` does it on its own.
- **Real Unicode data.** Tables are generated by a committed script from the Unicode
  18.0.0 data files, the full grapheme break test suite and the official emoji test files
  run, and every code point is cross-checked against glibc and the `wcwidth` package.
- **Typed errors.** A wrong type raises `TypeError`, a wrong value `ValueError`, at the
  call and with a short message.

```python
from cellstr import cell_len, iter_cells, truncate_detailed

cell_len("αβ─", ambiguous=2)  # -> 6
cell_len("a\tb", tabsize=8)  # -> 9
[c.width for c in iter_cells("a你🇯🇵")]  # -> [1, 2, 2]
truncate_detailed("hello world", 8).truncated  # -> True
```

Public API: `cell_len`, `char_width`, `grapheme_width`, `iter_graphemes`, `iter_cells`
(`Cell`), `cell_slice`, `ljust`, `rjust`, `center`, `fit`, `truncate`,
`truncate_detailed` (`Truncation`), `expand_tabs`, `strip_ansi`, `UNICODE_VERSION`, and
the `Align` and `Position` literal types. Every function is fully typed and documented.

## Command line

```
$ printf 'abc\n你好\n' | cellstr measure
3
4
$ printf '/usr/local/lib/python3/site-packages\n' | cellstr truncate 16 --position middle
/usr/lo...ckages
$ printf 'id\n12345\n' | cellstr pad 8 --align right
      id
   12345
```

Commands: `measure` (`--max`), `truncate N`, `pad N`, `fit N` and `slice START [STOP]`,
all with `--ambiguous` and `--tabsize`. `cellstr --help` lists runnable examples.

## Terminals disagree

There is no standard for how many cells a character takes, and terminals differ on
ambiguous-width characters, emoji ZWJ sequences and variation selectors. `cellstr`
follows Markus Kuhn's reference `wcwidth` for single code points and
measures emoji sequences as one glyph, as terminals with grapheme support draw them.
The [guide](https://github.com/JaviLianes8/cellstr/blob/main/GUIDE.md) has the exact rules, concrete examples of where terminals differ, a
recipe for code point by code point measuring, and every difference from glibc and the
`wcwidth` package.

## Why

The `wcwidth` package is the established choice, and version 0.9.2 covers much of this
ground: string width with escape sequences, `clip`, `ljust`, `rjust`, `center`, `wrap`,
grapheme iteration, an ambiguous-width option and correction tables for specific
terminals, with an optional C extension. Use it when you need wrapping or per-terminal
corrections.

`cellstr` is smaller and aimed at fitting text into columns: truncation with a suffix at
the end, the start or the middle (`truncate`, `truncate_detailed`, `fit`), slicing that
keeps whole clusters and every escape sequence, `iter_cells` records with columns, a
`cellstr` command for shell pipelines, and typed errors raised at the call. Its widths
are compared code point by code point with glibc and `wcwidth`, and the
[guide](https://github.com/JaviLianes8/cellstr/blob/main/GUIDE.md#differences-from-other-measurers) lists every difference. Both
packages are typed and have no dependencies.
